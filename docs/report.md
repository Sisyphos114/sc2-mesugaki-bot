# 星际争霸 II 本地 LLM 对手 · 项目报告

## 1. 项目概述

把本地大模型接进《星际争霸 II》，让它作为对手陪你打 1v1。

和"让 AI 直接操作游戏"的常见设想不同，这个项目采用**分层架构**：大模型只负责宏观战术和嘴炮，单位级操作交给确定性的脚本。原因是硬性的——星标的微操窗口是毫秒级，而本地 9B 模型单次推理需要 2~18 秒，两者的时间尺度差了两个数量级。

> 一句话：大模型当教练和指挥官，脚本当手。

## 2. 需求与约束

| 约束 | 说明 | 采用的做法 |
| --- | --- | --- |
| 人类必须能真正参战 | 暴雪官方 API 只能开 Bot vs 电脑，正常客户端无法加入 API 对局 | 使用 python-sc2 7.3.0 原生的 `Human` 玩家类型，框架自己拉起两个客户端 |
| 不能只用虫族 | 现成的 DI-star 预训练模型只支持 ZvZ | 放弃 DI-star，自写执行层，任意种族可配 |
| 不能调用 Qoder 内置模型 | Qoder 内置 DeepSeek 没有对外 API，也没有 headless CLI | 改用本机已有的 llama.cpp + GGUF 模型 |
| 显存只有 6 GB | 9B Q4 模型权重约 5.3 GB | `-ngl 36` 部分层卸载到 GPU，上下文压到 2048 |
| 推理不能拖垮对局 | 实时模式下每步都有时间预算 | 决策放在独立线程，HTTP 调用不进入游戏循环；模型挂了对局照常进行 |

## 3. 架构

```
┌──────────────────────────────┐
│  人类客户端（SC2，窗口化）      │  ← 玩家操作
└──────────────┬───────────────┘
               │ 同一局 game
┌──────────────┴───────────────┐
│  main.py                     │  python-sc2 run_game(realtime=True)
│  Human(race) + Bot(race)     │  两个 SC2 进程，端口由 python-sc2 分配
└──────────────┬───────────────┘
               │
┌──────────────┴───────────────┐        ┌───────────────────────┐
│  bot.py  ExecutorBot         │ 状态 → │  brain.py  Brain       │
│  · 补农民 / 造人口            │ ─────→ │  后台线程，每 20s 一次  │
│  · 开局建筑顺序               │        │  HTTP → llama-server   │
│  · 出兵、侦察、进攻/防守       │ ←───── │  ← JSON 指令 + 台词     │
└──────────────────────────────┘  指令   └───────────┬───────────┘
                                                     │
                                         ┌───────────┴───────────┐
                                         │ llama.cpp (OpenAI 兼容) │
                                         │ Qwen3.5-9B Q4_K_M      │
                                         └───────────────────────┘
```

### 三层职责

1. **游戏层**：python-sc2 负责协议、双客户端、地图、回放。
2. **执行层**（`bot.py`）：全部确定性逻辑，不依赖网络。即使模型服务挂掉，它也会按默认打法继续打。
3. **决策层**（`brain.py`）：独立守护线程，定时把局势摘要发给模型，解析回 JSON 指令。

## 4. 关键实现

### 4.1 指令协议

模型每次返回固定 JSON：

```json
{
  "stance": "macro | defend | harass | all_in",
  "attack_at_army": 15-100,
  "composition": "zealot | stalker | balanced",
  "expand": true,
  "say": "一句嘴炮"
}
```

解析层会做字段校验和范围钳制；任何解析失败都保留上一条指令，不会中断对局。

### 4.2 状态摘要

每约 1 秒推送一次，只放模型真正需要的宏观量，避免长 prompt 拖慢推理：

- 时间、人口、农民数、基地数、矿/气
- 部队构成（zealot / stalker 数量）
- 兵营数量、可见敌方单位数、已探到的敌方基地数

### 4.3 兼容性补丁

SC2 5.0.17 会下发 python-sc2 自带数据里不存在的 ability id。原版 `Unit.orders` 遇到未知 id 直接抛 `KeyError: 4135`，而 `train()` 内部依赖 `len(structure.orders)`，导致出兵逻辑整段失效。

处理方式是在 `bot.py` 顶部替换 `Unit.orders`，跳过未知指令：

```python
_sc2_unit.Unit.orders = property(_safe_orders)
```

不修改第三方库源码，升级 python-sc2 后补丁会自动被覆盖。

### 4.4 雌小鬼人设

在 system prompt 中约束：

- 战术字段照常输出，`say` 单独用雌小鬼口吻
- 强制关闭 thinking（`/no_think` + `chat_template_kwargs.enable_thinking=false`）
- `say` 只许嘲讽，禁止出现数字、兵种、资源量、战术解释（否则模型会把自己的进攻阈值说漏）
- 禁止脏话、人身威胁、色情内容

关闭 thinking 前单次生成会被推理过程占满 token（35 秒且拿不到内容）；关闭后稳定在 **2~3 秒**。

## 5. 验证

共三轮实机对局（人族 vs 神族 bot，`KairosJunctionLE`，`realtime=True`）：

| 阶段 | 现象 |
| --- | --- |
| 启动 | 两个 SC2 客户端约 17 秒进入对局，人类窗口可正常操作 |
| 经济 | 农民 12 → 23，人口 13/15 → 24/31，人口卡住时会自动补水晶塔 |
| 科技 | 水晶塔 → 传送门 → 控制核心 → 二兵营 → 气矿 |
| 扩张 | 约 2 分 15 秒开二矿 |
| 侦察 | 45 秒派农民探路，日志中可见"敌兵 11/12"（对方 SCV） |
| 决策 | 空闲 2.8 秒/次；对局负载下 12~18 秒/次 |
| 稳定性 | 修复 ability 4135 后，最后一局 0 异常 |

模型指令示例：

```
[brain]  122s stance=defend army>=20 comp=stalker expand=False (15.5s)
        「杂鱼~才不是看你笨手笨脚才留你活口的呢~哼~就这~？」
```

## 6. 局限

1. **执行层很弱**：前 2 分钟基本只有 1 个兵营出兵，3 分钟后才铺到 4 兵营；没有微操（不会拉兵、不走位、不躲 AOE），纯 A 地板。
2. **只实现了神族**，即 bot 固定打 Protoss；玩家可任选种族。
3. **决策粒度粗**：模型只能在"运营 / 防守 / 骚扰 / 全军压上"之间选，并给出一个兵力阈值，无法指定具体兵种数量或进攻路线。
4. **模型质量受限于显存**：6 GB 只能跑 9B Q4 + 36 层卸载，复杂局势下的判断不稳定（会出现阵容与局势不匹配）。
5. **人类端需自行点击进入**：框架拉起窗口后，玩家仍要走正常进入对局的流程。

## 7. 后续可做

- 执行层：加入折跃门、不朽/巨像、简单的集火与后撤逻辑
- 侦察：持续用侦察单位刷新敌方视野，让决策层看到真实兵力
- 决策：把"操作风格"（激进/保守）与"兵力阈值"解耦，避免模型给出自相矛盾的指令
- 多族：把建造表数据化，支持 Terran / Zerg 执行层
- 语音：接 Windows SAPI，把 `say` 直接念出来
